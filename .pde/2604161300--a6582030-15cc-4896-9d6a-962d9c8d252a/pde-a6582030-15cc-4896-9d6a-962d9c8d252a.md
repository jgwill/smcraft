## Original Prompt

> Build a small CLI that watches a directory and notifies via webhook when a markdown file changes

## Primary Intent

**Action:** build
**Target:** CLI tool that watches a directory and sends webhook notifications on markdown file changes
**Urgency:** session
**Confidence:** 95%

## Secondary Intents

1. **implement** — directory watcher for filesystem change events _(explicit)_
2. **filter** — change events to markdown files only (.md extension) _(implicit)_
   - depends on: directory watcher implemented
3. **send** — HTTP POST webhook payload on detected markdown change _(explicit)_
   - depends on: markdown file change detected
4. **parse** — CLI arguments for directory path and webhook URL _(implicit)_
5. **define** — webhook payload schema (file path, event type, timestamp) _(implicit)_
6. **handle** — errors for invalid directory, unreachable webhook, or permission issues _(implicit)_
   - depends on: core watcher and webhook sender implemented
7. **choose** — language and filesystem-watch library (e.g. Node/chokidar, Python/watchdog, Go/fsnotify) _(implicit)_

- markdown files are identified by .md extension
- notification means HTTP POST to the webhook URL
- 'small' implies minimal dependencies and single-file or minimal-file implementation
- watching is continuous/persistent until process is killed

## Ambiguity Flags

- **"'small' — no language specified"**
  - Suggestion: Clarify preferred language; Node.js (chokidar) or Python (watchdog) are common minimal choices
- **"Webhook notification format unspecified"**
  - Suggestion: Confirm expected payload: at minimum { path, event, timestamp } as JSON
- **"Recursive vs. top-level directory watching unspecified"**
  - Suggestion: Clarify whether subdirectories should be watched; default to recursive for most use cases
- **"Which change events to notify on — created, modified, deleted, renamed?"**
  - Suggestion: Assume all events by default, or confirm if only 'modified' is wanted
- **"Debounce behavior unspecified — editors often write files multiple times per save"**
  - Suggestion: Add optional debounce flag (e.g. --debounce 300ms) to avoid duplicate webhook calls
